# 节点参考条目表

## 使用方式

- “联想新物件”生成待采纳条目，每行包含找图勾选框、独立搜索短语、细节描述。
- 名称与描述可以编辑。采纳时保留所有条目及其勾选状态；只有勾选行用于找图。
- 多项分别执行语义搜索，按“任一满足”合并并去重。描述不自动拼入搜索。取消勾选不删除设定，也不排除包含该物件的图片。
- 点选一行，再点“补充细节”，建议只针对这一行。采纳仅更新描述，保留行 ID、搜索短语、勾选状态及原有描述。
- 已有长文本完整保留为 AI 的约束，可通过“将原文整理为条目…”预览提取结果，也可手动添加条目。原有说明本身不会隐式参与条目搜索。
- 全部取消勾选会提示至少选择一项，不回退到全图库搜索。调整图片墙中的强度仍实时生效；重新按剩余条目找图保留同名条件的强度。
- 节点锁定后不可编辑内容，仍可改变找图勾选。恢复操作同时恢复条目 ID、内容和勾选状态。

## 实现与保护

`creative_node_workflow` 新增 `entries_json`、`proposal_entries_json`；`creative_node_versions` 新增 `entries_json`。迁移仅添加字段，不自动转换原文。

新条目请求要求 JSON additions 数组，对字段类型、非空内容和重复项做检查。格式失败重试一次，仍失败则显示错误，不把散文猜测拆分成条目。旧供应商的长文本建议继续兼容。条目 ID 和选择状态由软件管理。

生成过程中若用户改变了目标行名称或描述，细节建议不能覆盖新内容；节点删除后结果不能落到其他节点。节点删除撤销也保留 workflow 数据。

结构化格式可以校验，但内容是否符合世界观、搜索短语是否足够准确仍受模型能力和图库索引影响，保留用户编辑、采纳和恢复步骤。

## 测试

测试数据库独立于用户数据库：`/tmp/eidory-reference-rows-qa/eidory.sqlite3`。测试程序使用独立 bundle ID `local.eidory.rowscheck`。

真实本地模型 `qwen3.6-35b-a3b-uncensored-hauhaucs-aggressive` 的屏幕案例：

1. 赛博朋克贫民住所，原文为破旧的床、回收零件柜、禁止豪华新家具；生成五条新物件，包括废旧蓄电池组、零件周转箱、旧显示器改装示波器等。
2. 在建议表取消后三项，再采纳：保存五行、只搜索前两行。图片墙显示两个独立条件，关系为任一满足。
3. 将两项匹配强度由 50 调到 85，图片墙从 8790 张变成 125 张，实时更新。
4. 正常退出并重新打开测试软件，五行及两项勾选状态保留。
5. 对未勾选的“旧显示器改装示波器”补充细节，采纳后只有第三行描述变化，其他行、名称、ID 和勾选均不变；原有描述保留。
6. 点击恢复，数据库内容与采纳细节前的条目、ID、选择状态完全一致。

7. 原文整理只提取床与零件柜两行，没有把“禁止出现豪华新家具”转成正向找图目标；可预览或放弃。
8. 全部取消勾选后点击找图，界面提示至少勾选一项，没有开始全图库搜索。
9. 手动添加“手工拼装工作灯”，编辑为“手工拼装低功率工作灯”，新增行、名称与描述正确保存。
10. 锁定节点后添加和编辑内容按钮禁用，仍可勾选现有条目；最终布局不再在说明与表格之间扩张空白。

回归合计 325 项通过（按模块分进程执行；最终修复后重跑了受影响的 45 项）。修复了屏幕测试发现的原文整理模式校验和放弃建议后按钮未恢复问题。

新增回归覆盖格式错误与重试、旧库迁移、待采纳选择保存、多目标搜索合并去重、取消全部、强度保持、节点切换、内容锁定、过期建议拒绝、原描述保留、删除撤销、表格高度。

完整日志与屏幕操作后的数据快照位于 `build/qa/reference-rows/`（不纳入 Git）。最初合并运行全部 Qt 测试时，两个固定等待 80ms 的既有实时滑块测试在系统负载下出现超时；随后按测试文件分别运行，避免同一 Qt 进程累积大量测试窗口，结果见 `regression-results.json`。

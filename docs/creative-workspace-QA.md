# 创作工作区改进与验收记录

日期：2026-09-10。测试环境：macOS、Python 3.12。
主体屏幕案例使用 PySide6 6.11.2；稳定性对照后正式运行库固定为 6.9.3，并重建安装包复测。

## 本轮交付

- 中部按“构思 → 找参考 → 已收集 → 看板”组织操作，右侧保留当前项目和节点。
- 项目各自保存主题、补充约束和节点搜索状态；自由灵感探索与项目设定分开。
- AI 节点补全先显示为建议，支持编辑后采纳、追加选中文段、放弃、恢复与锁定。
- 节点找图复用已接受的保留／排除筛选器，支持实时强度调整、返回候选与多选恢复。
- 每个节点里的参考图片可以记录独立用途说明。
- 灵感方向可以变为创作节点，并带入所选图片中与该方向匹配的图片。
- AI 分组先预览，允许改名、移动图片、合并、取消或保存。
- 看板增加节点分区、便签、撤销与重做；适应画布时包含文字。
- 创作参考包导出 HTML、JSON、原始参考文件和看板 PNG。

## 屏幕测试方式

实际启动桌面软件，使用原生鼠标、键盘、文件选择器和界面观察完成以下案例。
AI 补全、灵感生成、分组命名调用现有本地 LM Studio，模型为
`qwen3.6-35b-a3b-uncensored-hauhaucs-aggressive`。

测试数据库是现有图库的 SQLite 备份，位于 `/tmp/eidory-creative-qa`。
原图库有 23,134 条图片记录；通过软件导入 4 张颜色／名称测试图片后，副本为 23,138 条。
测试项目、筛选、参考说明和看板编辑均写入副本，未修改用户实际图库或移动源图片。

开发测试使用独立 QA 应用；最终又复制正式 `dist/Eidory.app`，仅修改副本的
bundle ID 与数据目录环境设置，用其实际冻结代码启动并读取项目、图片和看板。

## 测试中发现并修正

- 灵感转换后项目下拉框的节点／图片数量未刷新。
- 根节点直接图片数与包含子节点的图片数表达含糊。
- 返回候选时只恢复第一张选中图。
- 灵感搜索的强度滑块在布局迁移后被隐藏。
- 看板适应范围漏掉标题和便签；新增便签可能盖在图片上。
- 本地模型的分组命名 JSON 可能出现在 reasoning 字段；现在请求关闭推理，并提取其中合法的结构化结果。
- macOS 原生辅助功能扫描 Qt 表格选择项时可触发崩溃；现在保留按钮和编辑器的正常接口，树、列表和自定义画布作为整体暴露。

## 自动化回归与边界

运行命令为 `.venv/bin/python -m pytest -q`。最终单进程完整回归连续两次
**476 项通过**（55.00 秒、43.92 秒），结果见 `build/qa/accepted-final-regression.log`
和 `build/qa/runtime-stability-regression.log`。依赖检查和安装包签名完整性检查通过。

普通单进程 pytest 在反复创建主窗口时出现过 PySide 原生崩溃，堆栈位置不固定。
原生堆栈包含 `PySide::SignalManager::retrieveMetaObject` 的空指针访问。
关闭循环 GC、保留窗口引用、换用 minimal 平台和独立测试进程都未稳定解决，
相关运行器试验未作为修复保留。
Qt 官方论坛上有相同堆栈的[第一手问题报告](https://forum.qt.io/topic/164861/pyside6-crash-null-deref-in-signalmanager-retrievemetaobject-via-stale-qtablewidgetitem-wrapper-address-reuse-6.10.2-and-6.11.1)，
但不能据此断言本项目的内部触发原因完全相同。
改用 6.9.3 后整套回归正常完成，因此固定依赖并重建应用。
另修正了一个旧鼠标测试：按真实交互顺序构造和发送按下、移动、释放事件，避免 Qt 6.9
合成事件共享设备位置导致测试中的拖动距离为零。没有修改断言或放宽尺寸要求。

本轮原生屏幕测试未复现上述批量测试进程崩溃。辅助功能兼容处理的代价是
树／图片墙／看板里的单项不再逐个出现在 AX 树中；正常控件、编辑器、鼠标和键盘操作保留。
没有把这些案例等同于全平台、所有文件格式或所有 AI 服务的全面认证。

# 重复对比导航与进度修复

删除或移除当前近似对中的图片后，旧代码按“有任意一个图片 ID 相同”定位当前组。如果当前对是 A/B，B 被移除，而很后面的 A/C 仍有效，窗口会跳到 A/C。测试精确复现了从首组跳到“第 286 / 416 组”的行为。刷新或撤销也可能误匹配到其他共享图片的组。

## 行为

- 近似对由完整的两个图片 ID 识别，共享一张图片不再表示同一组。
- 完全重复文件族的成员减少时保留其原组身份，可继续比较剩余副本。
- 本次检测的组顺序固定。结果更新或撤销不会重排浏览队列。
- 当前组仍有效时保持同一组；当前组消失时选择原队列中第一个仍有效的后续组，后面没有待处理组才返回最后一个前序组。
- “上一组 / 下一组”按钮和方向键每次只移动一个队列位置，无循环或按住连发。
- 顶部区分“待处理第 X / Y 组”和“本次检测编号 #N / 总数”，并显示已解决数量。结果更新时解释当前组被保留或已进入下一组。
- 撤销把组插回原检测顺序，同时保留当前可见组。

## 验证

- 两个旧行为回归先确认失败：首组被处理后跳到第 286 组；同一结果刷新后误跳到第一个共享图片的组。
- 48 项重复检测 / 对比相关测试通过；其中连续点击 300 次“下一组”逐次验证位置只增加 1。
- 109 项相关回归通过，包含真实临时图库中的移除、下一组、撤销，以及现有删除、预览和主题行为。
- 修复版已安装并通过签名检查。在真实图库重新检测得到 416 组后，实际点击按钮逐次核对 `1 → 2 → … → 11 → 10 → … → 1`，每步正确。新的待处理位置、检测编号和已解决数量已在原生窗口确认；应用留在第一个待处理组。
- 回归和构建日志位于 `build/qa/duplicate-navigation/`。
- 此次更新前的应用与数据库一致性备份位于 `build/rollback/duplicate-navigation-20261029/`。备份时图片记录为 28,488，数据库 `quick_check` 为 `ok`。

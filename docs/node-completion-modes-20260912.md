# AI 节点补全：实物与细节分离

## 用法

- **联想新物件**：提出当前节点里尚未出现的实体物件，并给出可见用途。物件、地点、世界观、穿戴等节点可用；时间、光线、构图、表面等节点使用细节模式。
- **补充细节**：深化已经存在的主体，包括造型、材质、状态、已有光线和感受。原对象通常自带的部件可以描述；不能借细节模式增加其他独立物件。
- 滑块向右：实物模式增加种类与联想跨度，细节模式增加视觉设计的大胆程度。世界观、已有设定、其他节点约束不随滑块放宽。
- 两者均生成待采纳建议。先编辑、采纳，再用于找参考；可恢复上次采纳前内容。锁定节点不生成。
- 批量补全按节点职责选择模式，跳过锁定或已有待采纳建议的节点。

## 实现与约束

单节点、批量与失败重试共用模式提示词。AI 输出独立命名的结构化条目；软件负责保留用户原文和换行。保留旧格式解析以兼容不支持结构化输出的服务。

实物模式要求每项与现有物件不同，排除换名、原有部件和堆形容词。低档最多 2 项，高档最多 8 项；数量上限也写入 JSON schema，但不强求凑数。细节模式使用单独的提示词和字段说明。

模型只复述原文时重试一次；仍失败则报错，不再生成固定套话冒充有效补全。搜索词优先保留新参考目标，避免被长篇旧说明挤出 240 字限制。

使用 reasoning_effort=low、单次最多 4000 tokens，以留出约束检查空间；不支持该参数的服务继续沿用已有兼容回退。真实本地模型 qwen3.6-35b-a3b-uncensored-hauhaucs-aggressive 实测单次约半分钟到一分钟，具体由模型与机器决定。

这套约束不能证明模型每次都有新颖、合理的设计；软件保证保留原文和采纳流程，语义合理性仍要通过待采纳建议审阅。模型构想中的工程功能不代表已验证技术。

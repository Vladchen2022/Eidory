# 性能优化与验证记录 · 2026-09-18

本次保留现有功能、界面和搜索规则，集中改善看板加载、页面切换、数据库访问、索引更新和后台任务收尾。

## 改动

| 部分 | 调整 | 用户可感知的变化 |
|---|---|---|
| 看板图片 | 后台解码，先建立布局；加载结果校验所属项目 | 大看板打开时更快恢复操作，快速切换不会把旧项目图片写进新看板 |
| 高清图片 | 按当前可见区域与缩放加载，离开后释放高清副本 | 放大仍可查看细节，减少不必要的高清图片常驻 |
| 构思与看板切换 | 合并一次导航触发的重复刷新，跳过隐藏区域的构建 | 页面往返减少重复查询和控件重建 |
| 图片属性 | 批量读取等级与用途，批量写入评级 | 多选图片时减少逐张查询 |
| 用途备注 | 连续输入合并保存；切图、切页和退出前立即保存 | 减少写入，同时保留最后输入的内容 |
| 语义检索 | 缓存最近的文本向量；小范围只计算对应图片 | 相同语句和小范围搜索减少重复计算；仍使用精确检索 |
| 索引更新 | 采用增量更新，定期合并内存索引 | 新图片完成索引时不再每次重新读取整个向量库 |
| 后台任务 | 限制并发，取消尚未执行的旧搜索，分批处理界面事件 | 减少任务互相争抢资源和事件堆积造成的卡顿 |
| 保存与退出 | 缩略图原子替换，正常退出等待任务安全结束 | 降低半写入文件、运行中线程被销毁的风险 |
| 异常诊断 | 本地轮转日志、异常堆栈、主线程延迟记录 | 后续出现问题时有定位依据；没有增加远程遥测 |

图片异步加载还校验了位置、尺寸、裁切、灰度、固定和撤销状态。无法读取的图片显示文件名，避免自动反复重试；恢复读取后清除失败提示。

带 EXIF 旋转信息的照片在看板上按显示方向计算比例；新导入时也记录旋转后的宽高，使图片墙与缩略图一致。没有批量改写现有图库的尺寸元数据。

## 同条件性能对比

同一台机器、同一份升级前数据、同一脚本，交替运行旧代码 `5824840` 与新代码各三次，取中位数。每轮清空看板的进程内图片缓存；操作系统磁盘缓存没有清空，因此这不是磁盘冷启动测试。

| 场景 | 优化前 | 优化后 |
|---|---:|---:|
| 54 张看板建立场景并交还操作权 | 78.5 ms | 6.4 ms |
| 200 张看板建立场景并交还操作权 | 285.6 ms | 13.8 ms |
| 500 张看板建立场景并交还操作权 | 693.7 ms | 29.0 ms |
| 500 张看板全部初始图片就绪 | 700.4 ms | 382.7 ms |
| 54 张多选属性刷新，P95 | 45.5 ms | 7.9 ms |
| 属性刷新平均数据库连接次数 | 59.1 | 5.1 |
| 200 张范围的向量计算，P95 | 0.557 ms | 0.069 ms |
| 连续 30 次索引新增与小范围计算 | 246.0 ms | 1.9 ms |
| 上述过程的向量数据库重读次数，含初始化 | 31 | 1 |

“交还操作权”和“图片就绪”分开计时，避免把异步等待误算成零成本。向量基准使用固定随机种子的 23,500 × 512 测试向量，不包含模型首次加载、文本推理、磁盘读取和结果界面刷新，不能把计算耗时等同于一次完整搜索。启动及全图库向量计算没有作为本轮主要收益承诺。

记录：`build/qa/performance-final-comparison.json`；可复跑脚本：`scripts/benchmark_interaction.py`。脚本必须指定独立的 `EIDORY_DATA_DIR`，会改动测试库的界面设置。

最后的图片方向修正后又复测一次，500 张看板交还操作权为 27.4 ms、全部初始图片就绪为 394.4 ms，未出现相关性能回退。记录在 `build/qa/performance-orientation-timing.json`。

## 自动验证与边界

回归覆盖精确搜索结果、增量索引、缓存上限、缩略图失败保护、旧加载结果丢弃、异步像素替换不改变布局、备注保存及后台任务退出。最终测试和长时记录见本文件末尾。

测试中发现并修正了异步图片尺寸舍入导致的布局漂移、不可读图片提示缺失、恢复后提示残留，以及旋转照片的宽高问题。复验中出现过 Qt 测试进程在切换窗口或垃圾回收时崩溃；独立看板与旧主窗口测试随后补齐了解码线程等待、计时器停止、失败后的窗口关闭和引用保留，并重新验证。不能将测试窗口销毁顺序的问题直接当作用户日常操作崩溃率的估计。

- 完整自动回归：**646 项通过**，410.70 秒，`build/qa/performance-release-verified.log`。
- 最后追加的导入尺寸修正：扫描、看板、图片属性和性能专项 **57 项通过**，8.46 秒，`build/qa/performance-import-orientation-final.log`。
- 主性能实现长时测试：60 分钟、720 次操作步骤，没有记录到异常，数据库检查为 `ok`，安全退出完成。RSS 最后约 8 分钟保持在 1,521 MiB 附近。
- 导航刷新和图片尺寸修正后的追加长时测试：30 分钟、361 次操作步骤，没有记录到异常，数据库检查为 `ok`，安全退出完成；结束时 RSS 约 1,404 MiB。
- 长时测试使用 500 张图片，反复切换构思/看板、放大、评级、备注、分区、窗口尺寸及后台读取。它们先于最后的不可读图片提示与 EXIF 边界修正启动；最后两项由专项回归和屏幕案例另行覆盖。日志为 `build/qa/performance-soak.json` 与 `build/qa/performance-final-soak.json`。
- 长时事件循环最大间隔分别为 1,044 ms 与 830 ms；这说明仍有短时延迟，不能据此声称所有操作恒定流畅。RSS 包含 Qt、图片缓存和分配器保留内存，这不是“零内存泄漏”的证明。
- `/Applications/Eidory.app` 已构建安装，签名验证通过。安装后的真实数据库检查为 `ok`；图片、项目与节点内容、参考关系、等级和备注与备份一致，浏览产生的 `updated_at` 更新时间除外。记录在 `build/qa/performance-real-data-final.json`。

这些验证只能覆盖记录中的场景。模型首次加载、外部模型服务速度、损坏的媒体解码库，以及超大文件或慢磁盘仍可能造成等待；本次没有承诺任意环境下零崩溃或恒定帧率。

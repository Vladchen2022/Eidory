# 创作流程升级 · 人工验收与回退

基线提交 `a913a42`，实施分支 `codex/creative-workflow-upgrade`。

## 如何验收

建议先新建一个测试项目，使用主题「赛博朋克财团研发室，三位工程师围绕一台新款人形机器人改造」。每项除了检查按钮是否工作，也检查结果是否减少了你实际创作中的麻烦。以下复选框留给你亲自验收。

新增的项目总览、方案版本、功能准备检查和可编辑项目包，统一放在工作区右上方的「项目工具」菜单。原来的 HTML 创作参考包继续保留。

### 1. AI 根据节点职责工作

- [ ] 在故事性插画的「人物」填入恰好三位工程师及明确分工，点击「完善人物方案」。检查建议围绕人物身份、服装轮廓、动作差异展开，证件、手套不会冒充第四位人物。
- [ ] 在「地点」点击「补充空间组成」，检查建议是空间结构、布局单元或设施；在「物件」点击「联想新物件」，检查它补充的是合理实物。
- [ ] 新建角色设计项目，查看「穿戴」的「完善穿戴方案」；世界观、氛围等整体说明节点仍以短文处理。已锁定节点仍跳过，建议必须采纳才改变正式内容。

**是否有意义：** 同一主题下，人物、空间、物件的建议有明确分工。若仍大量生成不属于该节点的内容，记下主题、节点和原文，这是需要继续调优的失败案例。AI 内容质量仍有随机性，程序能够保证格式校验与保留原内容，不能保证每次灵感都值得采用。

### 2. 创作内容与找图语句分开

- [ ] 在人物节点点击「检查与编辑搜索目标」。将核心目标改为「科幻工程师 工作服」，把某条人物的实际找图语句改成「多人协作维修」。保存后，确认上面的创作说明和细节没有被改写。
- [ ] 取消某条搜索目标的勾选，再「保存并找图」。确认该目标不出现在本次保留条件中；勾选状态会保存。
- [ ] 保留核心主体，同时只勾选少数新增条目。确认不会因为新增工具等局部细节，丢掉机器人或人物这个核心目标。

**是否有意义：** 能把故事里的名称转换成图库容易匹配的视觉表达，不必破坏原有构思。细节描述不会被自动塞入每个搜索目标。

### 3. 多目标结果更容易查看

- [ ] 同时搜索「科幻工程师 工作服」和「机器人关节」。在「候选视图」中分别选择综合推荐和单独目标，观察图片及数量的变化。
- [ ] 在顶部直接拖动每条语义条件的宽松/严格滑块，确认结果数和目标下拉选项里的数量一起更新。
- [ ] 查看图片上的命中标记；对已收集图片，原有项目收集标记应继续存在。「按工具栏排序」可回到所选的时间等排序方式。

**是否有意义：** 不用反复重开搜索，就能判断哪个目标缺图。综合推荐会轮流取各目标靠前的结果并去重，不保证语义相关性百分之百，也不会把各目标无关的结果强行变成好参考。

### 4. 将收集与最终采用分开

- [ ] 在具体节点的「已收集」选一张图片，在右侧「用途」设置「主参考」和「造型」，再选另一张设置「暂不采用」。
- [ ] 用已收集区域的「参考等级」分别筛选主参考、备选、暂不采用，核对数量、图片角标及用途是否正确。
- [ ] 切换节点再回来，检查等级和用途仍在；把暂不采用改回备选，确认图片可找回，没有被删除。

**是否有意义：** 收集很多图后仍能迅速找到真正要用的图。等级和用途按节点记录，同一图片在不同节点可以有不同用途。

### 5. 看板成为可整理的分区

- [ ] 在项目根节点进入「看板」，点击「按节点分区」。检查各节点有独立区域，主参考较大，长看板会自动分列。
- [ ] 拖动分区标题区域，确认该区图片整体跟随；双击标题锁定，再拖动和重新「按节点分区」，确认锁定区位置与大小保持。
- [ ] 切换到图片墙再回来。然后向项目加入一张新图，检查原有布局保留，新图安排在新增区域；「适应全部」可看到整个画布。

**是否有意义：** 整理好的一部分不会因补充参考被反复打乱。分区锁定保护整体移动和自动整理，区内单张图片仍可手动调整；标题便签之外的自定义便签保留原位。

### 6. 项目总览指出下一步

- [ ] 打开「项目工具 → 项目总览」，检查每个节点的设定状态、参考数量、主参考数量以及下一步建议。
- [ ] 将「时间」设成「无需参考图」；把某个已经足够的节点设成「参考已齐」。确认不会强迫每个节点都收集图片。
- [ ] 给一个节点生成建议但暂不采纳，再看总览，应提示先审阅 AI 建议。

**是否有意义：** 能快速找到实际缺口，而不是靠图片越多就越接近完成的假进度。项目根节点显示直接关联数量，子节点的图片各归其对应行。

### 7. 保存和恢复完整方案

- [ ] 打开「项目工具 → 方案版本」，保存「方案 A」。然后修改主题、某条勾选、参考等级和看板位置。
- [ ] 再打开方案版本，选 A 检查差异预览，恢复。核对主题、节点文字、条目勾选、参考关联、用途与看板布局一起恢复。
- [ ] 找到「恢复前自动保存」，可以切回刚才修改后的状态。修改项目主题或补充信息后打开总览，应提示复核；已确定节点不会被自动重写。

**是否有意义：** 可以比较创作方向并放心尝试，不用依赖记忆重建整套配置。方案快照只保存项目状态与图片链接，不能恢复已被物理删除的源图片。

### 8. 阅读大小与内容层级

- [ ] 在「设置」调整「文字大小」，例如从 13 到 14，确认文字立即变化，而界面密度与主题仍可独立选择。
- [ ] 重启后查看字号是否保留；切换浅色和深色主题，检查输入、条目表、侧栏仍可读。
- [ ] 生成一份 AI 建议，检查已有内容与待采纳区域有明显区分。试着切换「构思/找参考/已收集/看板」，确认按钮状态和实际页面一致。

**是否有意义：** 能用适合自己屏幕和视力的文字大小，并清楚区分已经确定与尚未采纳的内容。原有左右保留/排除筛选布局继续保留。

### 9. 准备检查反映真实能力

- [ ] 打开「功能准备检查」，先点「检查准备情况」。检查图库可用/丢失数量、按模型列出的语义索引覆盖数量。
- [ ] 查看 AI 模型服务状态，区别「模型可见，尚未验证生成」和真正生成成功。
- [ ] 点「测试 AI 生成」，检查能否得到一句实际正文。若服务未启动、模型不存在或认证失败，应显示对应处理方向，不能误报就绪。

**是否有意义：** 搜不到图或 AI 不工作时，能区分图库、索引和文本模型问题。索引记录存在不等于模型已加载；缺少索引的新导入图片仍需建立语义索引。

### 10. 项目迁移与日常保护

- [ ] 用「导出可编辑项目包」选择连同素材打包，再导入其中的 `project.eidory.json`。检查导入预览的节点数、图片数和缺失数量；导入会新建项目，不覆盖原项目。
- [ ] 在导入项目中查看条目勾选、独立搜索目标、参考等级、看板分区和方案历史，并确认还可以编辑。素材会复制到应用数据目录，因此删除外部项目包不会断开已导入的图片链接。
- [ ] 在设置查看自动备份状态。打开「恢复数据库」选择备份，先核对图片/项目/节点数量；不打算恢复时点 No。实际恢复前仍会自动备份当前数据库。

**是否有意义：** 能把可继续编辑的方案带走，并在数据库出问题前有恢复点。项目包保留搜索目标，但导入时清空绑定旧图库的临时筛选和范围，需要重新找图。自动数据库备份每天一次，仅保留最近 7 份自动备份，不清理手动备份；它保护元数据，不复制图库源文件。

## 回退准备与操作

Git 标签 `checkpoint/before-workflow-upgrade-20260915`。
完整备份目录 `build/rollback/workflow-upgrade-20260915/` 包含旧 `Eidory.app`、完整应用 `data`、`repository.bundle` 和 `manifest.json`。备份前已正常退出应用；备份 SQLite 检查为 `ok`。基线为 23,497 张图片、7 个项目、73 个节点、169 个节点图片关联、18 条用途说明。

**仅回退程序：** 正常退出 Eidory，把当前应用另外保存，将备份中的 `Eidory.app` 恢复到 `/Applications/Eidory.app`。本次数据库变更为新增表，旧程序可继续使用原数据。

**完整回到升级前：** 先退出应用，把当前应用和 `~/Library/Application Support/Eidory` 另存；然后恢复备份的旧应用，并将整个 `data` 恢复为 `~/Library/Application Support/Eidory`。不要直接覆盖仍在运行的数据库。

**只回退源码：** 从上述标签新建一个回退分支，或在独立目录从 `repository.bundle` 恢复仓库。不要用会丢掉其他未提交工作的方法强制重置当前目录。

完整数据回退会撤回升级后产生的编辑，因此应先保存当前数据。外部图库原始文件不在应用数据备份中，本次升级不修改它们。测试副本、导出包和回退目录不提交到 Git。

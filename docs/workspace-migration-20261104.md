# 工作区迁移（0.1.3）

入口：设置 → **工作区迁移 / 换电脑…**。

## 旧电脑

1. 选择“完整迁移包”，默认携带检索模型；API Key 默认不携带。
2. 选择一个新的迁移包目录，例如外置磁盘中的 `Eidory迁移`。
3. 点击“检查并导出”。核对图片、向量、项目数量、空间估计、缺失图片与历史关联异常，再开始复制。
4. 把整个迁移包目录复制到新电脑或保留在外置磁盘上。

可以暂停。再次选择同一目录和相同选项即可继续，使用第一次建立的数据库快照。快照之后的新修改不会混入；如果源文件已变化，应重新导出到新目录。

“关联现有图片”模式不携带图库外部原图，但仍携带缩略图、AI 候选、替换备份、回收区和检索模型。新电脑需要指定原图库在当地的位置，软件按文件内容逐张校验。适合已经搬好图片或使用同一块外置磁盘的情况。

## 新电脑

1. 安装同版或更新版 Eidory，打开设置 → 工作区迁移 → 从迁移包恢复。
2. 读取迁移包，选择新工作区的父目录和新文件夹名。关联模式需选择各图片根目录。
3. 等待内容校验与恢复。恢复中断后，保持同一包和同一目标，再点继续恢复。
4. 完成后选择“切换并重启”，或稍后在“切换 / 回退”中切换。

完整迁移得到的文件夹包含 `data` 和 `media`，应整体保留。不要单独删除 `data` 中的 AI 备份或回收文件。各个工作区彼此独立，不提供两台设备间的双向同步。

## 保留范围

- 原图与文件夹层级（完整模式），既有图片 ID、向量 BLOB、模型身份及标签。
- 收藏、用户标签、笔记、画笔标记、项目、节点、关联、布局及历史快照。
- 缩略图、AI 放大批次与待审核结果、生成候选、替换原图备份、回收区记录。
- 软件设置、当前 Jina 检索模型和必要代码依赖的确切缓存版本。

不重复打标签，不重新计算已有图片向量。语义搜索仍需为**新输入的查询文字**计算一个查询向量，这是正常检索步骤。原来尚未建好索引或没有标签的图片不会因迁移自动补齐。

日志、旧安装包备份、旧数据库备份不进入迁移包；当前数据库使用 SQLite 一致性快照。导出前另存当前数据库备份。

ComfyUI、LM Studio、Ollama 等外部服务及其放大/生成/识图模型，需要在新电脑另行安装配置。API Key 如未勾选携带，需重新填写；勾选时为明文迁移。已有结果和标签可直接使用，无需为了迁移重新调用这些服务。

## 保护与回退

- 复制采用临时文件、SHA-256 校验、完成后原子改名。关联图片即使文件时间改变，只要内容一致，重绑时间记录，不清空向量或 AI 标签。
- 恢复写入独立暂存目录，校验完成后才发布成新工作区。拒绝覆盖现有目录、越界路径和符号链接逃逸。
- 保留原工作区和切换历史。软件正常退出后才提交切换，再启动新进程。选定工作区损坏或磁盘未连接时，尝试回到上一个可用工作区并提示。
- 恢复后自动文件监听、放大队列暂停；旧电脑正在执行的远程任务停止跟踪并保留原状态记录，需要时手动重试；待审核结果不自动替换原图。
- 如果源数据库已存在历史关联异常，将原样保留并写进 `data/migration-report.json`；迁移新引入的关联错误会阻止恢复。普通“恢复数据库”仍执行原有严格校验。
